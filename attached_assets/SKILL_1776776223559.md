# Auditoría de www / no-www y canonical (Replit)

Esta skill comprueba si una web desplegada en Replit con dominio personalizado tiene **bien resuelta la dualidad `www` vs sin `www`** desde el punto de vista de SEO. Replit no ofrece un toggle nativo de redirect 301, así que la lógica debe estar en el código del servidor (o en Cloudflare delante). Si no está, Google indexa dos webs duplicadas y diluye autoridad.

## Cuándo usar

- El usuario acaba de conectar un dominio personalizado en Replit Deployments.
- Reporta que la web no carga sin `www` (o al revés).
- Pide "revisar SEO técnico", "auditar dominio", "revisar canonical", "evitar penalización de Google".
- Tiene varias webs en Replit y quiere homogeneizar el tratamiento.

## Lo que hay que verificar (checklist)

Ejecuta los pasos en orden y reporta hallazgos con severidad (🔴 crítico / 🟡 mejorable / 🟢 ok).

### 1. DNS y dominios enlazados en Replit
- Tanto `dominio.com` como `www.dominio.com` deben estar **enlazados en Deployments → Settings → Domains** para que Replit emita SSL para ambos.
- En el registrar (Hostinger, Namecheap, etc.) deben existir **dos registros A** apuntando a la misma IP de Replit: uno con hostname `@` y otro con hostname `www`. Más los dos TXT de verificación que da Replit (uno por cada hostname).
- No debe haber registros `AAAA` para esos hostnames (Replit solo soporta A).
- Si usa Cloudflare, el proxy debe estar en gris (DNS only); en naranja Replit no puede renovar el SSL.

### 2. Comprobación HTTP en vivo
Hacer 4 requests con `curl -I -L` y observar status + `Location`:

```bash
curl -sI https://dominio.com/        | head -n 20
curl -sI https://www.dominio.com/    | head -n 20
curl -sI http://dominio.com/         | head -n 20
curl -sI http://www.dominio.com/     | head -n 20
```

Resultado esperado (ejemplo si la canónica es **sin www**):
- `https://dominio.com/` → `200 OK`
- `https://www.dominio.com/` → `301` con `Location: https://dominio.com/`
- Las versiones `http://` deben terminar también en la canónica `https://` con un único salto.

🔴 Banderas rojas:
- Ambas versiones devuelven `200` (no hay redirect → contenido duplicado).
- Más de un salto (`http://www → https://www → https://apex` = cadena, debe ser un único 301).
- Redirect a `302` en vez de `301`.
- Bucle infinito (típico si Cloudflare está en SSL "Flexible").

### 3. Implementación del redirect en el código

Buscar middleware o configuración que fuerce el host canónico. Stacks comunes en Replit:

#### Express / Node (TypeScript o JS) — `server/index.ts` o similar
Patrón correcto:
```ts
app.set("trust proxy", 1); // imprescindible detrás del proxy de Replit
app.use((req, res, next) => {
  if (process.env.NODE_ENV !== "production") return next();
  const host = req.headers.host ?? "";
  const CANONICAL = "dominio.com"; // sin www
  if (host === `www.${CANONICAL}`) {
    return res.redirect(301, `https://${CANONICAL}${req.originalUrl}`);
  }
  next();
});
```
Verificar:
- `app.set("trust proxy", 1)` está presente (si no, `req.protocol` y `req.secure` mienten).
- El middleware está **antes** de las rutas y del `serveStatic`.
- Solo actúa en `production` (no romper el dev en Replit Workspace).
- Usa `301`, no `302`.
- No reescribe el path/query: usa `req.originalUrl`.

#### Next.js — `next.config.js`
```js
async redirects() {
  return [{
    source: "/:path*",
    has: [{ type: "host", value: "www.dominio.com" }],
    destination: "https://dominio.com/:path*",
    permanent: true, // = 301
  }];
}
```

#### Vite + Express (template fullstack-js de Replit)
Igual que Express. El middleware va en `server/index.ts` antes de `registerRoutes` y de `setupVite`/`serveStatic`.

#### Flask
```python
@app.before_request
def canonical_host():
    if not app.debug and request.host.startswith("www."):
        return redirect(f"https://{request.host[4:]}{request.full_path}", code=301)
```

#### FastAPI
```python
@app.middleware("http")
async def canonical_host(request, call_next):
    host = request.headers.get("host", "")
    if host.startswith("www."):
        return RedirectResponse(
            url=str(request.url).replace(f"//{host}", f"//{host[4:]}", 1),
            status_code=301,
        )
    return await call_next(request)
```

#### Static Deployment (Replit Static)
Crear `_redirects` en la raíz publicada:
```
https://www.dominio.com/* https://dominio.com/:splat 301!
```

### 4. Etiqueta `rel="canonical"` en el HTML

Buscar todas las apariciones (en React/Vite suele estar en `index.html`, en Next.js en `<Head>` o `metadata`, en Flask en plantillas Jinja):

```bash
grep -rn 'rel="canonical"' --include='*.html' --include='*.tsx' --include='*.ts' --include='*.jsx' --include='*.js' --include='*.py'
```

Verificar:
- 🔴 **No debe haber más de una** etiqueta `<link rel="canonical">` por página renderizada. Si hay una en `index.html` y otra inyectada por React/Helmet, cuenta como duplicada.
- 🔴 La URL del canonical debe coincidir exactamente con la versión a la que redirige el 301 (mismo host, mismo esquema `https://`, misma política de barra final). Si rediriges a `https://dominio.com` pero el canonical dice `https://www.dominio.com`, los señales se contradicen.
- 🟡 Idealmente cada página tiene su propio canonical (self-referencing) apuntando a su propia URL canónica, no todas al home.
- 🟡 No usar `http://` en el canonical aunque la web esté en `https://`.

### 5. Sitemap y robots.txt
- `sitemap.xml`: todas las URLs deben estar en la **versión canónica** (mismo host que el redirect destino). Si lista `www.` y rediriges a sin `www.`, el sitemap se invalida.
- `robots.txt` debe declarar el sitemap con la URL canónica:
  ```
  Sitemap: https://dominio.com/sitemap.xml
  ```
- 🟡 Si hay sitemap generado dinámicamente, revisar el código que lo construye (suele leer `req.host` y arrastra el host equivocado).

### 6. Open Graph y meta sociales
`<meta property="og:url">` debe coincidir con el canonical. Mismo criterio para Twitter Cards.

### 7. Enlaces internos
```bash
grep -rn 'https://www\.dominio\.com\|https://dominio\.com' --include='*.tsx' --include='*.ts' --include='*.jsx' --include='*.js' --include='*.html' --include='*.md'
```
Todos los enlaces internos absolutos deben usar la versión canónica. Lo ideal es usar rutas relativas (`/about`) y no hardcodear el host.

### 8. SSL
Las dos respuestas a `curl -vI https://dominio.com` y `https://www.dominio.com` deben mostrar certificado válido (Replit lo emite automáticamente si ambos hosts están enlazados en Deployments). Si una da error de certificado, falta enlazarlo en Replit.

## Cómo elegir la versión canónica

Si el usuario no ha decidido aún:
- **Sin www** → recomendado por defecto: URL más limpia, estándar moderno.
- **Con www** → mejor si el sitio va a usar muchos subdominios, CDN con CNAME flattening, o aislamiento de cookies.

Una vez elegida, **no cambiar más adelante** sin un plan de migración (los 301 nuevos sumarían un salto a los antiguos).

## Plantilla de informe al usuario

Devolver siempre algo así:

```markdown
## Auditoría www / canonical — dominio.com

**Versión canónica detectada:** sin www (https://dominio.com)

### Estado
- 🟢 DNS: ambos hostnames apuntan a la IP de Replit
- 🟢 SSL: certificado válido en ambos
- 🔴 Redirect 301: NO implementado — www. devuelve 200 en vez de redirigir
- 🟡 Canonical: presente pero apunta a https://www.dominio.com (contradice la decisión)
- 🟢 Sitemap: usa la versión sin www
- 🟢 Enlaces internos: relativos

### Acciones propuestas
1. Añadir middleware de redirect 301 en `server/index.ts` (snippet incluido)
2. Corregir el `<link rel="canonical">` en `client/index.html` para que apunte a https://dominio.com
3. Re-desplegar y verificar con `curl -I` que www. devuelve 301

¿Aplico los cambios?
```

## Reglas de actuación

- **No tocar nada sin confirmar la versión canónica con el usuario.**
- Aplicar primero los arreglos del código (redirect + canonical), después pedir un re-deploy, y volver a correr los `curl` de la sección 2 para validar.
- No introducir el redirect en modo desarrollo (rompería el preview de Replit).
- Si el proyecto usa Cloudflare, preferir el redirect en código de todos modos: es portable y no depende del registrar.
- Nunca duplicar el canonical: si ya hay uno en `index.html` y se está usando React Helmet / Next `<Head>` / etc., elegir un solo lugar y eliminar el otro.

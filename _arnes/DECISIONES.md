# DECISIONES — registro inmutable. Se añade, jamás se borra ni se revierte sin decisión humana.

Formato: `- [fecha] [seccion|global] DECISIÓN — porqué`

Ejemplo: `- [2026-07-10] hero Se usó grid y no flex en features porque el original colapsa a 1 col con grid-template.`

- [2026-07-30] [global] No se marcará `APROBADO_SPECS: sí`, `✅` ni `AUDIT_PASS` de forma retroactiva desde la sesión constructora.
- [2026-07-30] [global] La primera regularización agregó la home en una sola fila; una revisión independiente posterior exigió sustituirla por las doce secciones reales de `captura/secciones.json` sin presentar evidencia page-level como section-level.
- [2026-07-30] [home] La paridad no se forzará ocultando mapas, fotografías o logos que sí cargan en el candidato cuando la fuente pública falla en resolver lazy media durante la captura.
- [2026-07-30] [global] Resend y el cambio de dominio quedan fuera del PR final hasta autorización expresa.
- [2026-07-31] [blog-privacy] Los campos administrativos destinados a IA que contengan la palabra completa `patient` o `paciente` se rechazan de forma fail-closed; el editor reformula el tema sin ese marcador. El contenido público mantiene el detector estrecho para no censurar artículos legítimos.
- [2026-07-31] [blog-privacy] La frontera fail-closed administrativa se amplía a `name/nombre`, incluyendo snake_case y camelCase, después de que Code Review demostrara que parsear etiquetas, wrappers y puntuación no converge. Esta ampliación no se aplica a contenido público ni imágenes.
- [2026-07-31] [blog-privacy] `additionalContext` conserva uso local para seleccionar fuentes, tags y brief, pero se elimina del payload en la única frontera del proveedor de borradores. No se intentará inferir nombres lowercase sin etiqueta mediante regex o listas finitas: el juez demostró falsos positivos clínicos y evasiones; la protección firme es que el texto libre no salga literalmente.
- [2026-07-31] [legacy-admin] El modo Express `auth-off` exige simultáneamente peer socket loopback, `req.ip` efectivo loopback y autoridad `Host`/`X-Forwarded-Host` completamente loopback. Un túnel o reverse proxy de desarrollo con cliente remoto no hereda privilegios aunque conecte al servidor por `127.0.0.1`.
- [2026-07-31] [blog-privacy] Las etiquetas plurales `patients/pacientes/names/nombres` solo se tratan como marcadores sensibles cuando llevan un separador explícito, incluso si marcador, separador y valor viven en campos distintos. El uso editorial plural sin separador permanece permitido.
- [2026-07-31] [blog-planner] El ángulo de un candidato verificado viaja como `providerEditorialContext`, separado del `additionalContext` humano. Solo las rutas que verificaron o construyeron el candidato aportan ese argumento; la frontera del proveedor elimina el campo humano y restaura exclusivamente el ángulo con proveniencia.
- [2026-07-31] [replit-preview] `npm run dev` permanece limitado a loopback. La vista previa pública de Replit usa `dev:replit`, carga primero los mismos `.env*` de Next y se niega a arrancar si cualquiera de los modos admin solicita `off/disabled`.
- [2026-07-31] [blog-images] El guard de imágenes conserva los límites entre título, excerpt, heading y contenido. Las etiquetas inequívocas de paciente o nombre legal/completo fallan en cerrado; solo `Name/Nombre/Names/Nombres` genéricos aplican excepciones editoriales para evitar falsos positivos.
- [2026-07-31] [blog-privacy] La frontera administrativa previa a IA incluye `client/cliente`, sus plurales etiquetados y labels de teléfono EN/ES. Los números internacionales con prefijo `+` o `00` se detectan por longitud E.164 compatible sin exponerlos al proveedor.
- [2026-07-31] [blog-topic-judge] El historial no recupera títulos ni keywords en claro. El juez recibe únicamente perfiles locales de enums cerrados: categoría, pilar, etapa, formato, intención y faceta canónica; esto recupera señal de canibalización sin reabrir PII.
- [2026-07-31] [blog-plans] Una selección persistida consulta primero, sin mutar, que el planning run siga completado y sin post. Privacidad permanece antes de toda mutación; selección y claim condicionado siguen después de los gates y resuelven la concurrencia con un único ganador.
- [2026-07-31] [next-admin] El modo Next `auth-off` solo acepta tráfico directo local o una cadena proxy íntegramente loopback. Headers presentes pero vacíos, malformados, mixtos o contradictorios fallan en cerrado; `Forwarded` se rechaza porque no se interpreta en este modo.
- [2026-07-31] [blog-plans] El claim condicionado del planning run y la selección de su candidato son una sola transacción: primero gana el cambio `completed -> running` y solo el ganador modifica `selected`. Un fallo revierte ambos cambios y el conflicto único `23505` se traduce centralmente a 409 en Next y Express.
- [2026-07-31] [legacy-admin] Express `auth-off` aplica el mismo contrato proxy fail-closed que Next además de socket y `req.ip`: valida XFF/X-Real-IP completos, exige cadena ante metadata proxy y rechaza `Forwarded`, incluidos headers presentes pero vacíos.
- [2026-07-31] [blog-privacy] Los identificadores no etiquetados se reconstruyen solo en ventanas contiguas de dos o tres campos y deben formar un teléfono completo válido o una dirección postal completa. Se aceptan fragmentos extremos de un dígito y separadores telefónicos aislados; no se concatena globalmente todo el input.
- [2026-07-31] [blog-topic-judge] Cuando un borrador guiado procede de un candidato persistido, su categoría, pilar, etapa, formato, intención y ángulo verificados son autoritativos. Un request no puede sustituirlos; privacidad se evalúa antes de enviar al juez el perfil canónico y el ángulo trusted.
- [2026-07-31] [blog-privacy] Los SSN partidos se reconstruyen en las mismas ventanas adyacentes de dos o tres campos. La validación conserva el formato 3-2-4, admite cualquier corte de nueve dígitos cuando existe prosa previa y los fragmentos posteriores son numéricos, y usa contexto fuerte `SSN/Social Security/seguro social` para tolerar prosa final. Los años 1900–2099 quedan excluidos salvo etiqueta SSN inequívoca.
